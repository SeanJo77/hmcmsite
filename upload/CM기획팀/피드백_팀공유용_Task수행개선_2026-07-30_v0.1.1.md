## 1. 취지

- 대상: 전 프로젝트 `prompt/`·`context-migration/` 로그 73건 전수 분석
- 목적: 개인 평가 아님 / 작업 방식 개선

---

## 2. 전사 공통 개선 과제 (7건)

- **로그 서식 불일치** — 표준 템플릿·입도(로그 1건의 단위) 기준 부재. 1턴짜리~49턴짜리 로그 혼재.
- **일부 프로젝트 로그 0건**(20/21 프로젝트) — 코드는 완성됐으나 추적 기록 없음. 코드 위치도 규칙(`Code/` 폴더) 이탈.
- **버전 표기 파편화** — 파일명 버전 ≠ 문서 내 버전, 다수 사례.
- **산출물 실재성 미확인** — 로그상 "완료"이나 실제 파일 부재.
- **근거자료 사후 투입** — 착수 후 근거자료 추가 → 재작업 반복. 여러 팀원 공통 발생.

---

## 3. 잘못된 사례 (재발 방지용)

| 유형 | 요약 | 재발 방지 |
| :--- | :--- | :--- |
| 근거자료 사후 투입 | 착수 후 자료 추가 → 산출물 20회+ 재생성 | 착수 시 참고자료 목록 선(先) 고정 |
| 로그 허위 기재 | 메모리 파일 생성 기록 O, 실제 파일 X | 로그 기재 전 `ls`(파일 목록 확인 명령)로 실재 확인 |
| 산출물 소실 | 이미지 등 산출물 10건+ 추후 미확인 | 착수 시 수용 기준 선(先) 확정 |
| 평면 저장 | 예외 규칙([F7], 폴더 자동생성 불가 시 대체 절차)을 정상 환경에도 적용 → 날짜 폴더 미분리 | 정상 환경은 표준 폴더 구조 사용 |
| 변경이력 누락 | 산출물 12건 중 변경이력 표 포함 0건 | 모든 문건 변경이력 표 필수(F6) |
| INPUT 미기록 | 로그 14건 사용자 입력 원문 누락, 2회 지적 후 재발 | INPUT 원문 그대로 기재(요약 금지) |
| 검증 오탐 | 1일차 전체 PASS → 2일차 재검증 시 결함 47건 | 검증 시 산식·계산 근거 첨부 |

## 4. 전파 권장 우수 사례

- **체크섬 회귀 검증** — `md5sum`(파일 내용 변경 여부를 확인하는 체크섬 명령)으로 작업 전후 파일 대조. 참조 파괴 사고 예방.
- **출력 채널 통제** — "화면 표출 금지" 등 산출 방식 명시. 토큰 절감.
- **배제 범위 사전 차단** — 미다룰 범위 착수 시 선(先) 고지. 불필요 분기 감소.
- **근거 우선순위 사전 지정** — 참고자료 열람 순서 선(先) 확정. 사후 투입 예방.
- **입력 원문 코드펜스 보존** — 사용자 입력을 코드블록으로 원문 보존.
- **INPUT 3자 분리 표기** — 원문 / 시스템 응답 / 담당자 주석 구분 기재.
- **사실 단위 메모리 파일링** — 사실 1건 = 파일 1개. 검색·갱신 용이.
- **Plan 선행 → 승인 → 실행** — 계획 선제시 → 승인 → 실행. 요구 번복 감소 확인.
- **Self-audit 문서화**(self-audit: 지침 준수 여부를 스스로 점검·기록하는 문서) — 품질 관리 보조.
- **검증 환경 노하우 메모** — 반복 타임아웃 등 이슈 기록. 팀 전체 시행착오 감소.
