# 검측_자료통합_프로세스_v9

> **💡 검측(Inspection)이란?**
> 건설 현장에서 특정 공종의 시공이 완료되었을 때 다음 후속 공정으로 넘어가기 전, 해당 시공물이 **설계도면, 시방서 및 각종 품질 기준에 적합하게 시공되었는지를 현장에서 실측·확인하여 합격/불합격 여부를 최종 판정하는 핵심 품질관리 절차**를 의미합니다.

---

검측 프로세스를 입체적으로 파악하기 위해, 참고한 주요 폴더 및 파일자료를 분류하였습니다.

| 폴더명                    | 주요 내용 및 특징                                                                      |
| :--------------------- | :------------------------------------------------------------------------------ |
| **99_품질관리계획**          | A-1 작업 및 검측 절차서(Hold Point 지정), B-1(118건) CodeNo 체크리스트 구조                       |
| **99_검측 황선필선임**        | 실제 생성된 검측의뢰서, 사진대지, 통보서 실물                                                      |
| **99_검측 옹벽 강지영선임**     | KCS(국가건설기준)와 연계된 10단계 시공 절차, 자재 승인 등 선행 행정과 HP/WP 병목 통제 논리, 정량적 실측 수치 기록 의무화 실무 |
| **98_첨부 검측자료**         | 건설현장 검측업무 메뉴얼(QMS-0085) 및 건설공사 사업관리방식 검토기준 및 업무수행지침                             |

## 2장. 통합 검측 프로세스 (ex-SSOC 연동 플로우차트)

> **💡 ex-SSOC 검측 화면 핵심 기능 (6대 탭)**
> 
> *   **검측의뢰서/통보서 검토**: 의뢰자가 입력한 공사명, 검측번호, 위치, 주요 내용을 시스템 내장 뷰어로 확인합니다.
> *   **체크리스트 판정**: 대공종 및 세부 코드별 표준 체크리스트의 적합 여부를 판정하며, 감사지적/설계지침이 자동 연동됩니다.
> *   **검측의뢰서 첨부서류**: 도면, 발파계획서 등 업로드된 PDF/CAD 파일을 웹 화면 상에서 즉시 열람합니다.
> *   **사진대지**: 현장에서 촬영한 시공 사진을 등록하고 사진명과 촬영일자를 연계하여 관리합니다.
> *   **3D Viewer (BIM)**: 3D BIM 뷰어를 내장하여 객체를 마우스로 클릭하고 이를 검측의뢰서와 매핑합니다.
> *   **반려 사유**: 보완 요청 및 불합격 판정 시 반려 사유를 명시하여 재검측의 이력을 기록합니다.

위 시스템 화면을 통해 검측 지점 도달 시, 배정된 등급별로 아래 매뉴얼 현장 흐름과 IT 시스템 상태값이 매핑되어 세부 프로세스가 수행됩니다.

### 2.1 상시검측 (WP)

```text
(현장 매뉴얼) [작업자] 시공 완료 ──▶ [공종담당자] 1차 확인/의뢰 ──▶ [공사책임자/품질관리실장] 검측/판정 ──(YES)──▶ 시공자 확인 및 대장 기록
(ex-SSOC)                             ┗[시공사 검측중]┛            ┗[시공사 확인완료]┛                ┗[시공사 통보완료]┛
```
*(※ 감독원은 실시간 입회 대신, 수시 점검 및 상시검측 관리대장 사후 확인을 수행)*

**[상시검측 5W1H 요약]**
- **Who (누가)**: 검측자(원도급사 공사책임자/품질관리실장)가 실측 판정, 시공자(현장대리인) 확인
- **When (언제)**: 절차서상 WP(상시검측)로 지정된 단계 도달 시
- **Where (어디서)**: 해당 공종 시공 현장
- **What (무엇을)**: 중요도가 상대적으로 낮거나 반복적인 시공 구조물
- **Why (왜)**: 시공사 자체 점검을 통한 품질 확보 및 감독원 업무 효율화
- **How (어떻게)**: 자체 실측/판정 후 상시검측 관리대장에 기록 (감독원은 사후 승인)

### 2.2 필수검측(공구) — 감독원이 직접 검측

```text
(현장 매뉴얼) [작업자] 시공 완료 ──▶ [공종담당자] 1차 확인 ──▶ [공사책임자] 2차 확인/의뢰 ──▶ [감독원(건설사업관리기술인)] 합동 실측/판정 ──(YES)──▶ 통보서 발급
(ex-SSOC)                                                     ┗[시공사 의뢰완료]┛           ┗[감독원 접수완료/검측완료]┛             ┗[감독원 통보완료]┛
```

**[필수검측(공구) 5W1H 요약]**
- **Who (누가)**: **감독원(건설사업관리기술인)**이 최종 판정
- **When (언제)**: 절차서상 공구용 HP(필수검측)로 지정된 단계 도달 시
- **Where (어디서)**: 해당 공종 시공 현장
- **What (무엇을)**: 매몰 부위나 구조 기능상 핵심이 되는 주요 구조물
- **Why (왜)**: 하자가 발생하면 복구하기 힘든 중요 공종의 안전성 담보
- **How (어떻게)**: 시공사 의뢰(ex-SSOC) → 감독원) 현장 합동 실측 및 채점 → 통보서 발급

### 2.3 필수검측(사업단) — 본사 직할 조직이 직접 검측

```text
(현장 매뉴얼) [작업자] 완료 ──▶ [공종담당자] 1차 확인 ──▶ [공사책임자] 2차 확인 ──▶ [감리 또는 감독원] 3차 확인/의뢰 ──▶ [공사시행부서원] 실측/판정 ──(YES)──▶ 통보서 발급
(ex-SSOC)                                                ┗[시공사 의뢰완료]┛     ┗[감독원 의뢰완료]┛               ┗[사업단 접수/검측완료]┛           ┗[사업단 통보완료]┛
```

**[필수검측(사업단) 5W1H 요약]**
- **Who (누가)**: 공사시행부서원(본사 직할 사업단/본부 등 소속 직원)이 최종 판정
- **When (언제)**: 절차서상 사업단용 HP(필수검측)로 지정된 단계 도달 시
- **Where (어디서)**: 해당 공종 시공 현장
- **What (무엇을)**: 사업단 차원의 교차 검증이 필요한 최상위 중요 구조물
- **Why (왜)**: 감리(또는 감독원)에게 집중된 권한의 분산 및 본사 조직의 철저한 다중 교차 점검
- **How (어떻게)**: 감리(또는 감독원) 경유 상위 의뢰 → 공사시행부서원 현장 실측 → 부서장 결재 후 통보서 발급
> 💡 ex-SSOC 시스템에서는 위 "의뢰" 단계가 검측의뢰서 작성·상신(위치/CodeNo 선택, 자동 연동 등)으로 디지털화되어 있습니다.

## 3장. 현행 문제점 및 해결방안 모색

현행 검측 시스템의 한계를 진단하고, 차세대 시스템에서 이를 극복하기 위한 구체적인 기술적 해결방안을 제시합니다.

### 3.1. 현행 검측 시스템 및 현장 실무의 근본적 문제점 (Pain Points)

### [1] 위치 정보 및 실측 데이터의 수동 입력 (휴먼 에러 유발)
*   **현상**: 검측 위치를 `STA. 18+681`과 같은 텍스트로 타이핑하고, 현장에서 줄자나 레벨기, 토탈스테이션으로 측정한 값을 다시 시스템에 수기로 입력합니다.
*   **문제**: 오타 발생률이 매우 높고 데이터 누락/수정의 위험이 큽니다. 디지털 계측장비와의 연동이 안 되어 추후 도면 기반의 GIS 시각화가 불가능합니다.

### [2] 검측 사진 증빙의 신뢰성 부족 (위변조 및 도용 리스크)
*   **현상**: 검측의 핵심 근거로 단순 휴대폰 사진이 업로드됩니다.
*   **문제**: 촬영 위치(어디서), 촬영 시점(언제), 촬영 방향(어디를)을 시스템적으로 엄격히 검증할 수 없습니다. 이로 인해 공정 직후가 아닌 나중에 찍은 사진이나, 타 구간의 사진을 도용하는 등의 문제가 발생해도 걸러낼 수 없어 사진이 진정한 '증거' 역할을 하지 못합니다.

### [3] 서류·승인 중심의 이중 업무 (행정의 비대화)
*   **현상**: 작업일보, 검측의뢰서, 통보서, 품질시험성과표, 사진대지 등에 동일한 내용을 반복해서 작성합니다. 전산 시스템(ex-SSOC)이 있음에도 불구하고 엑셀/CAD로 만든 자료를 다시 PDF로 변환해 첨부하는 이중 업무가 발생합니다.
*   **문제**: 검측의 본질이 "품질 확인"이 아닌 "서류 구색 맞추기"로 전락합니다. 문서 작성에 과도한 시간이 소요되어 정작 중요한 현장 점검 시간이 부족해집니다.

### [4] 정량적 데이터(수치) 부재 및 종이 문서(PDF) 기반의 한계
*   **현상**: 체크리스트가 "적합/확인/이상없음" 등 Pass/Fail 위주로 운영되며, 핵심 세부 데이터는 수기 작성된 대용량 PDF로 업로드됩니다.
*   **문제**: 노상 함수비, 평탄성, 다짐 횟수, 층두께 같은 정량적 데이터가 DB화되지 못합니다. 이로 인해 체크리스트 단위의 데이터 분석이나 통계 활용, 하자 발생 시 이력 역추적이 불가능한 '죽은 데이터'가 됩니다.

### [5] 검측 타이밍 지연 및 사각지대 발생 (책상 감리)
*   **현상**: 공정 압박으로 인해 철근 배근 후 콘크리트 타설이 먼저 진행되고 사후에 검측을 요청하거나, 고교각·하천 횡단부·터널 내부 등 접근이 곤란한 구간이 방치됩니다.
*   **문제**: 매몰 부위에 대한 필수 검측이 누락되거나, 현장에 직접 가지 않고 사무실에서 서류만 보고 결재를 내리는 '책상 감리'가 묵인되는 환경이 조성됩니다.

### [6] 데이터 파편화 및 BIM(디지털 트윈) 미연결
*   **현상**: 품질, 공정, 안전, 시험성과, 도면 데이터가 각각 다른 시스템과 포맷으로 분산되어 관리됩니다.
*   **문제**: 1년 뒤 특정 구간(KP)의 검측 이력을 찾으려면 엑셀, PDF 서류철, 사진 폴더를 모두 뒤져야 합니다. 또한 3D BIM 모델과 연동되지 않아 종이 도면을 들고 나가야 하는 아날로그적 방식이 유지됩니다.

### 3.2. 차세대 시스템 기술적 해결방안 (Solutions)

위의 한계점들을 타파하기 위해, Sat Pointer(위치)와 큐피드(사진), 그리고 모바일 DB화를 결합한 구체적인 해결책입니다.

### [1] 측위 장비 연동을 통한 데이터 디지털 전환 (Sat Pointer 적용)
*   **해결책**: STA 수동 텍스트 및 수기 입력 → **RTK(Sat Pointer)를 활용한 cm급 GIS 공간 좌표 및 실측 데이터의 자동 입력**으로 전환합니다. 측량 장비와 시스템이 직접 연동되어 오기입과 수작업이 100% 배제됩니다.

### [2] 3D 공간 기반 사진 증빙 자동화 및 위변조 방지 (큐피드 적용)
*   **해결책**: 수동 사진 첨부 → 스마트폰 및 드론 사진의 **EXIF(GPS, 방향각, 타임스탬프) 데이터를 시스템이 자동 추출하여 3D BIM 객체 위에 교차 검증 및 매핑**합니다. 특정 위치와 각도에서 찍지 않으면 증빙으로 인정되지 않도록 위변조를 원천 차단합니다.

### [3] 체크리스트 모바일 DB화 및 수치 중심 검측
*   **해결책**: HWP/Excel 스캔본(PDF 첨부) → BCMF 품질관리계획의 **118종 CodeNo 체크리스트를 모바일 App 내 정량적(수치 입력형) DB로 전환**합니다. Pass/Fail을 넘어 수치 기반의 빅데이터를 축적하여 품질 분석 및 AI 예측의 기반을 마련합니다.

### [4] 3D 디지털 트윈(BCMF) 기반 원스톱 타임라인 구축
*   **해결책**: 데이터 파편화 → **3D 모델(BCMF) 뷰어를 대시보드 중심에 배치**합니다. 도면 상의 특정 측점(KP) 모델링 객체를 클릭하면, 해당 부위의 검측 사진, 검측자, 시험성과, 합격 여부가 하나의 타임라인으로 통합 조회되도록 구현합니다.

### [5] 트래킹(Tracking) 기반 입회 증빙 강제화
*   **해결책**: 서면 승인 및 책상 감리 → 검측 시 **감리원의 이동 궤적(Tracking) 로그 및 GNSS 정밀도 품질 지표(FIX 상태 여부)**를 검측 승인서의 백그라운드 필수 증빙으로 결합합니다. 이를 통해 '현장 방문'을 시스템적으로 강제하고 검측 타이밍의 투명성을 완벽히 증명합니다.

## 4장. 차세대 검측 시스템 개념도 및 기획방향

Sat Pointer(위치 측정)·큐피드(사진 검증)·모바일 App(현장 입력)·관리자 Web(대시보드)이 검측 데이터 플랫폼으로 연동되고, CesiumJS 3D·GIS 시각화 엔진이 그 위에서 결과를 보여주는 차세대 시스템의 전체 구성도입니다.

```text
┌──────────────────────────────────────────────────────────────┐
│                차세대 통합 검측 시스템                          │

│ Sat Pointer │ 큐피드      │ 모바일 App  │ 관리자 Web          │
│ (위치 측정)  │ (사진 검증) │ (현장 입력) │ (대시보드)          │
├─────────────┴─────────────┴─────────────┴────────────────────┤
│                    검측 데이터 플랫폼                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────────┐ │
│  │의뢰·결재 │  │체크리스트│  │참고문서  │  │검측 대시보드 │ │
│  │모듈      │  │DB 모듈   │  │자동연동  │  │(GIS 히트맵)  │ │
│  │          │  │(118종)   │  │(감사지적 │  │              │ │
│  │          │  │          │  │ 설계지침 │  │              │ │
│  │          │  │          │  │ 안전가이드│  │              │ │
```
