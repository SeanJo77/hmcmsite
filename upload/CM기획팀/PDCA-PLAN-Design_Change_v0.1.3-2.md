# BCMF 설계변경 업무 기준 Plan v0.1.3-2

> **목적**  
> 이 문서는 BCMF 설계변경 화면을 설명하는 문서가 아니다.  
> 실무에서 `실정보고 접수`부터 `설계변경 승인`까지 어떤 순서로 흘러가야 하는지, BCMF가 그 흐름을 어디까지 기록하고 추적해야 하는지를 정리하는 업무 기준 문서다.

> **핵심 판단**  
> 실정보고 승인과 설계변경 승인은 별개의 승인 흐름이다.  
> 실정보고가 승인된 뒤에도 설계변경 서류를 다시 접수하고, 감독원 검토를 거쳐 설계변경 승인요청으로 넘어가야 한다.

---

## 0. 요약

| 구분 | 정리 |
|---|---|
| 문제 | 실정보고, 감독원 검토, 승인공문, 설계변경 승인요청, 최종 승인공문이 문서와 엑셀에 흩어져 현재 위치를 파악하기 어렵다. |
| 방향 | 실정보고와 설계변경을 한 건의 연속 프로세스로 관리하되, 승인 단계는 실정보고 승인과 설계변경 승인으로 분리한다. |
| 핵심 흐름 | `실정보고 접수 → 감독원 검토중 → 실정보고 승인요청중 → 실정보고 승인 → 설계변경 접수 → 감독원 검토중 → 설계변경 승인요청중 → 설계변경 승인` |
| BCMF 역할 | 온라인 결재 시스템이 아니라, 제출자료·검토자료·승인공문·이력·대기열을 같은 기준으로 추적하는 업무 관리 도구다. |

## 1. 개요 - 왜 BCMF로 관리해야 하나

### 1.1 현재 업무 문제

설계변경 1건은 실정보고, 기술검토의견서, 승인요청, 승인공문, 변경도면, 수량, 공사비, 관리대장까지 여러 자료로 나뉜다. 같은 정보를 반복 입력하고, 반려나 보완이 생기면 어느 검토 단계로 돌아가야 하는지 추적하기 어렵다.

| 구분    | 현재 문제                                   |
| ----- | --------------------------------------- |
| 자료 작성 | 실정보고서, 공사비 내역, 수량산출, 도면, 승인공문을 따로 관리    |
| 상태 파악 | 실정보고인지, 설계변경인지, 승인요청인지 한눈에 보기 어려움       |
| 검토 이력 | 감독원이 어떤 자료를 보고 확인했는지 추적하기 어려움           |
| 승인 추적 | 실정보고 승인과 설계변경 승인이 섞여 보이면 실제 승인 위치가 불명확함 |
| 반려 처리 | 누가 반려했는지, 어디로 재제출해야 하는지 이력으로 추적하기 어려움   |
| 금액 기준 | 5억원 미만과 5억원 이상 승인권자 안내가 명확히 필요함         |

### 1.2 목표 상태

BCMF는 설계변경 1건을 실정보고부터 최종 승인공문까지 하나의 업무 단위로 추적한다.

| 목표       | 설명                                   |
| -------- | ------------------------------------ |
| 절차 분리    | 실정보고 승인과 설계변경 승인을 별도 단계로 추적          |
| 검토 명확화   | 실정보고와 설계변경 모두 감독원 검토 단계를 가진다         |
| 대기열 명확화  | 로그인 사용자가 지금 처리해야 할 건만 업무대기열에 표시      |
| 서류 누락 방지 | 구비서류, 검토서류, 승인서류를 항목별로 확인            |
| 이력 보존    | 접수, 확인, 반려, 재제출, 승인요청, 공문등록을 이력으로 남김 |

> **핵심 가치**  
> “한 건의 설계변경을 실정보고부터 최종 승인공문까지 같은 기준으로 추적한다.”

### 1.3 대상 독자

| 독자       | 이 문서에서 확인할 것                     |
| -------- | -------------------------------- |
| 업무 기획자   | 설계변경 절차와 BCMF 적용 범위              |
| 시공사 담당자  | 내가 어느 단계에서 무엇을 등록해야 하는  지        |
| 감독원      | 검토확인, 반려, 기술검토의견서 등 검토서류 등록 기준   |
| 개발자/디자이너 | 진행현황, 서류, 이력의 업무상 의미         |
| 보고자      | 왜 이런 흐름으로 화면을 구성해야 하는지에 대한 설명 근거 |

## 2. 참고자료와 근거

### 2.1 기준 문서

| 참고자료 | 이 문서에서 사용하는 이유 |
|---|---|
| `건설공사 사업관리방식 검토기준 및 업무수행지침` 제67조 | 설계변경 사유 검토, 실정보고, 발주청 보고 기준 확인 |
| `[별표 3] 설계변경 및 계약금액의 조정 관련 건설사업관리 업무` | 설계변경과 계약금액 조정의 전체 업무 흐름 확인 |
| `QMS-0170 설계변경 및 계약금액조정 업무매뉴얼` | 현장 실무 용어, 제출자료, 승인권자, 처리기한 참고 |
| `공사관리 업무 프로세스_기술서_도공.pdf` | 설계변경 업무 흐름과 금액별 승인 기준 참고 |
| `고속도로 설계변경 절차 개선 방안` | 실정보고와 설계변경 승인 절차 개선 방향 참고 |

### 2.2 제67조에서 반영할 핵심

제67조는 설계변경을 단순한 승인 행위로 보지 않는다. 현장 조건 확인, 시공자 실정보고, 감독원 검토, 발주청 승인 또는 방침, 이후 설계변경 및 계약금액 조정으로 이어지는 업무로 본다.

| 기준                     | BCMF 반영                    |
| ---------------------- | -------------------------- |
| 설계도서와 현지여건이 다른 부분 파악   | 변경 사유, 변경개요, 현황도, 첨부자료 등록  |
| 시공자가 제출한 실정보고 내용 검토    | 실정보고 접수 후 감독원 검토 단계 운영     |
| 발주청에 설계변경을 위한 실정보고 제출  | 실정보고 승인요청중 단계 운영           |
| 발주청 승인 또는 방침 후 조치      | 실정보고 승인공문 등록 후 다음 단계 이동    |
| 설계변경 도면, 수량, 공사비 증감 검토 | 설계변경 접수 후 감독원 검토 단계 운영     |
| 경미한 사항과 긴급한 사항         | 일반 프로세스 확정 후 후속 버전에서 별도 처리 |

### 2.3 별표 3에서 반영할 핵심

별표 3은 설계변경 및 계약금액 조정을 시공자, 건설사업관리, 발주청, 승인권자의 순차 업무로 본다. 따라서 BCMF도 단순히 “승인요청중” 하나로 묶지 않고, 실정보고와 설계변경 접수를 나눠야 한다.

| 업무 위치 | 별표 3 흐름 | BCMF 반영 |
|---|---|---|
| 이슈 발생 | 현장여건, 물가변동, 설계변경 필요 발생 | 변경유형과 사유 입력 |
| 실정보고 | 시공자가 설계변경 필요서류 작성 | 실정보고 접수 |
| 검토 | 건설사업관리자가 기술검토 및 실정보고 | 감독원 검토중 |
| 발주청 승인 | 발주청이 설계변경 승인 또는 심의 | 실정보고 승인요청중, 실정보고 승인 |
| 설계변경 시행 | 계약금액 조정요청서 등 작성 | 설계변경 접수 |
| 최종 승인 | 사업단장 또는 건설처 승인 | 설계변경 승인요청중, 설계변경 승인 |

## 3. 업무 범위

이 문서는 실정보고 접수부터 설계변경 승인까지의 일반 업무 흐름을 다룬다. BCMF는 접수, 감독원 검토, 승인요청, 공문등록, 반려와 재제출 이력을 한 건 단위로 추적한다.

## 4. 용어와 주체

### 4.1 용어 기준

| 기준 문서 용어 | BCMF 용어 | 의미 |
|---|---|---|
| 시공자 | 시공사 | 실정보고 자료 작성, 보완, 승인요청, 공문등록을 처리 |
| 건설사업관리기술인 | 감독원 | 실정보고와 설계변경 서류를 검토하고 검토서류를 등록 |
| 발주청 | 사업단, 건설처 | 오프라인 승인 또는 방침 결정 주체 |
| 실정보고 | 실정보고 | 현장 실정과 변경 필요성을 보고하는 절차 |
| 설계변경 | 설계변경 | 승인 후 계약금액 조정으로 이어지는 변경 절차 |

### 4.2 역할별 책임

| 역할 | 책임 |
|---|---|
| 시공사 | 실정보고 작성, 구비서류 등록, 반려 보완, 설계변경 서류 제출, 승인공문 등록 |
| 감독원 | 실정보고 및 설계변경 서류 검토, 기술검토의견서 등 검토서류 등록, 확인, 반려 |
| 사업단 | 5억원 미만 건의 전결 승인 |
| 건설처 | 5억원 이상 건의 승인 |
| BCMF | 상태, 대기열, 첨부서류, 이력, 승인결과를 한 건 단위로 추적 |

## 5. 표준 진행현황

### 5.1 진행현황과 처리 기준

| 단계 | 진행현황 | 처리 주체 | BCMF에서 하는 일 |
|---:|---|---|---|
| 1 | 실정보고 접수 | 시공사 | 실정보고와 구비서류 제출 |
| 2 | 감독원 검토중 | 감독원 | 실정보고 검토, 검토서류 등록, 확인 또는 반려 |
| 3 | 실정보고 승인요청중 | 시공사 | 발주청 실정보고 승인 또는 방침 공문 등록 |
| 4 | 실정보고 승인 | 시공사 | 승인된 실정보고를 근거로 설계변경 서류 제출 |
| 5 | 설계변경 접수 | 시공사 | 설계변경 및 계약금액 조정 관련 서류 제출 |
| 6 | 감독원 검토중 | 감독원 | 설계변경 서류, 수량, 공사비, 계약금액 조정 근거 검토 |
| 7 | 설계변경 승인요청중 | 시공사 | 사업단장 전결 또는 건설처 승인공문 등록 |
| 8 | 설계변경 승인 | 시공사 | 최종 승인공문 또는 승인서류 등록 완료 |

진행현황은 단계 번호 순서대로 이동한다. 단, 감독원 검토 단계에서 반려되면 시공사가 보완 후 같은 검토 단계로 재제출한다. 같은 `감독원 검토중`이라도 앞 단계는 실정보고 검토이고, 뒤 단계는 설계변경 서류 검토다.

## 6. 서류 기준

서류는 문서 종류보다 업무 단계 기준으로 관리한다. BCMF는 각 단계에서 필요한 근거자료가 빠졌는지 확인하고, 승인 결과는 공문 또는 승인서류로 남긴다.

| 단계 | 등록 주체 | 서류 묶음 | 기준 |
|---|---|---|---|
| 실정보고 접수 | 시공사 | 실정보고(설계변경)사유서, 공사비증감 내역서, 변경공사비 내역서, 변경 수량산출서, 변경 설계도면, 변경 예정공정표, 기타 근거자료 | 감독원 검토와 발주청 승인 판단의 기본 자료 |
| 감독원 검토 | 감독원 | 기술검토의견서, 보완 검토자료, 현장 확인자료, 기타 검토 근거 | 시공사 제출자료와 분리해서 관리 |
| 실정보고 승인 | 시공사 | 실정보고 승인요청 공문, 실정보고 승인공문 또는 방침공문 | 실정보고 승인 상태 전환 근거 |
| 설계변경 접수 | 시공사 | 설계변경 승인요청서, 계약금액 조정 관련 내역, 변경도면·수량·공사비 보완본 | 실정보고 승인 이후 설계변경 절차 진행 근거 |
| 설계변경 승인 | 시공사 | 설계변경 승인요청 공문, 최종 승인공문 또는 승인서류 | 설계변경 승인 상태 전환 근거 |

실정보고 승인공문과 설계변경 승인공문은 서로 다른 문서다. 두 문서는 각각의 승인 단계를 완료시키는 근거로 따로 관리한다.

## 7. 반려와 보완 기준

반려는 최종 불승인이 아니라 보완 요청이다. 반려 사유는 반드시 입력해야 한다.

| 반려 위치 | 누가 반려 | 담당자가 해야 할 일 | 재제출 후 돌아가는 곳 |
|---|---|---|---|
| 실정보고 검토 | 감독원 | 반려 사유 확인 → 수정 → 재제출 | 감독원 검토중 |
