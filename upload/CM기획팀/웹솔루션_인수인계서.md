# HMCMkit 일일작업보고 웹솔루션 인수인계 가이드

본 문서는 일일작업보고 데이터 파싱 및 시각화 대시보드 시스템(HMCMkit)의 구동 소스코드 구조와 실행 방법을 웹솔루션팀에 전달하기 위해 작성되었습니다.
전달된 폴더는 불필요한 개발 부산물 및 테스트 데이터가 모두 제거된 **핵심 구동 필수 코드**로만 구성되어 있습니다.

---

## 1. 폴더 구조 및 역할 명세

전달받으신 폴더의 최상단에는 크게 `frontend` 폴더와 `backend` 폴더가 존재합니다.
아래 명세는 **실제 폴더 내 알파벳 정렬 순서(폴더 우선)**와 동일하게 구성되었습니다.

### 1-1. `backend/` (FastAPI 서버)
일일작업보고 HWP 데이터를 파싱하고 정규화(Location Verifier)하여 프론트엔드 API로 제공하는 백엔드 서버입니다.
모든 위치/장비 등의 사전 데이터는 로컬 JSON이 아닌 **PostgreSQL DB**와 직접 통신하여 처리됩니다.

* **`api/`**: 프론트엔드와 통신하는 FastAPI 라우팅 엔드포인트가 모여있는 폴더입니다.
  * `server.py`: FastAPI 라우팅 엔드포인트 및 메인 서버 로직입니다.
  * `server_config.py`: 서버 포트, CORS, DB 설정 등 서버 구동 환경 구성 파일입니다.
* **`config/`**: 공구별 HWP 텍스트 파싱을 위해 사용되는 기준 설정 및 텍스트 파일들이 모여있는 폴더입니다.
  * `extract_*.txt`: 각 공구(1~4공구)별 텍스트 추출용 정규식 또는 기준 데이터 파일들입니다.
* **`core/`**: HWPML 텍스트 파서, 위치 정합기(Location Verifier), 텍스트 전처리(Pipeline) 등 파이프라인의 핵심 파이썬 로직이 담긴 폴더입니다.
  * **`analyzer/`** : 파싱된 텍스트 블록의 의미를 분석하는 모듈.
    * `area_parser.py`: 공구별로 추출된 텍스트를 분석하여 공종, 위치, 인원, 장비 등 구체적인 항목으로 세분화(Parsing)하는 핵심 분석기입니다.
    * `area_reassembler.py`: 과거 파싱된 데이터를 원본 형태의 트리로 재조립(Round-trip)하던 로직입니다. (현재 메인 파이프라인(`server.py`)에서는 사용하지 않도록 주석 처리되어 있으나, 기존 코드 보존을 위해 남겨두었습니다.)
  * **`location_verifier/`** : 위치 데이터 정합성 검증 엔진. 추출된 위치 데이터가 정상 범위 내에 있는지 판정합니다.
    * `data_loader.py`: PostgreSQL DB의 `tb_it_loc_dictionary`, `tb_it_station_range_map` 테이블에서 위치 기준 데이터를 로드하여 메모리에 제공합니다.
    * `main_logic.py`: 1단계부터 9단계까지 이루어진 위치 검증 핵심 파이프라인을 관장합니다. 추출된 위치가 DB의 범위(Bounds)를 벗어나는지 대조하고 판정합니다.
    * `similarity_engine.py`: 텍스트 형태의 공종/위치명과 DB 사전 간의 코사인 유사도 및 형태소 기반 매칭 알고리즘을 수행하여 가장 비슷한 위치를 찾습니다.
    * `splitter.py`: 한 줄에 여러 위치가 쉼표 등으로 병기된 텍스트(예: "A구역, B구역 작업")를 개별 위치 객체로 쪼개주는(Split) 로직입니다.
    * `sta_utils.py`: "STA. 18+500 ~ 19+200"과 같은 측점(STA) 텍스트를 파싱하고 유효한 숫자형 데이터로 추출 및 변환하는 유틸리티입니다.
    * `text_utils.py`: 텍스트 정규화, 공백 제거, 특수문자 전처리 등 텍스트 검증을 돕는 유틸리티입니다.
    * `verifier.py`: 측점(STA) 범위 이탈 여부를 최종적으로 수학적으로 계산하고 검산(Verify)하는 모듈입니다.
  * **`pipeline/`** : 한글(HWP) 파일 텍스트 추출의 전처리를 담당하는 로직.
    * `hwpml_parser.py`: HWPML 구조의 XML을 파싱하여, 셀(Cell) 단위의 표(Table) 데이터를 추출하는 파서입니다.
    * `step0_extract_docinfo.py`: HWP 바이너리 문서에서 메타데이터(DocInfo)를 추출합니다.
    * `step1_hwp_to_xml.py`: HWP 바이너리를 XML 포맷으로 변환하여 이후 단계에서 파싱할 수 있도록 돕는 스크립트입니다.
* **`etl/`**: 데이터 추출(Extract), 변환(Transform), DB 적재(Load) 관련 파이프라인.
  * **`JSONtoDB/`**: 변환 및 적재 과정에서 생성되거나 참조되는 공구별 임시 JSON 데이터 폴더 모음입니다.
  * `extractor.py` / `utils.py`: 데이터 파이프라인 및 변환 유틸리티 파일입니다.
  * `loader.py`: 변환된 데이터를 DB에 실제 `INSERT` 하는 적재 모듈입니다.
  * `transformer.py`: 파싱된 JSON 결과물을 PostgreSQL DB 스키마 구조에 맞게 변형합니다.
* **`map_data/`**: 프론트엔드 대시보드 맵 렌더링 및 백엔드 범위 검증 시 공통으로 참조되는 로컬 GeoJSON 데이터 모음입니다 (`RoadDatas.json` 등).
* **`my_data/`**: 시스템 파싱 테스트 및 검증용 원본 일일작업보고(HWP) 샘플 파일들이 담긴 폴더입니다.
* **`static/`**: 개발용 파일 업로드 테스트 페이지(`upload.html`) 등 백엔드 테스트용 정적 리소스 폴더입니다.
* **`uploads/`**: 클라이언트(프론트엔드)에서 업로드한 파일이 파싱을 위해 임시로 저장되는 폴더입니다.
* **`.env`**: 백엔드 서버의 환경 변수 및 DB 접속 정보가 담긴 파일입니다. (※ 타겟 서버나 로컬 PC의 PostgreSQL 접속 정보(`DB_HOST`, `DB_PASSWORD` 등)에 맞게 내용을 반드시 수정해야 합니다.)
* **`requirements_server.txt`**: 백엔드 구동에 필요한 Python 패키지 의존성 목록.
* **`run_server.bat`**: 개발 환경에서 FastAPI 서버를 띄우기 위한 실행 스크립트.
* **`server_log.txt`**: 백엔드 서버 구동 시 파싱 결과 및 오류 로그가 실시간으로 기록되는 자동 생성 파일입니다. 따로 관리할 필요 없이 서버가 스스로 생성하고 덮어씁니다.

### 1-2. `frontend/` (React + Vite 클라이언트)
파싱된 일일작업보고 데이터를 표와 대시보드 맵(Map)으로 시각화하고 사용자 수정을 돕는 클라이언트 앱입니다.

* **`node_modules/`**: 프론트엔드 React 구동에 필요한 실제 라이브러리 패키지들이 설치되는 폴더입니다. (※ `npm install` 명령어 실행 시 `package-lock.json`을 기반으로 자동 다운로드되어 생성됩니다.)
* **`public/`**: 빌드 시 번들링되지 않고 그대로 복사되어 웹 렌더링에 사용되는 정적 자산(Static Assets) 폴더입니다.
  * `images/` : 지도 핀 아이콘 및 대시보드 그래픽 리소스.
  * **`phase0/`**: React 도입 이전(과거)에 순수 HTML/JS로 작성되었던 **HWP 문서 원본 뷰어 및 구버전 레이아웃 리소스들**입니다.
    * `daily-report-hwp.html` / `.js`: 원본 HWP 문서의 표 형태를 웹 브라우저 상에 그대로 모방하여 렌더링하기 위한 뷰어 뼈대입니다.
    * `daily-report-phase0.html` / `.js` / `daily-report-ksk.css`: 과거 구버전 레이아웃 에셋들로, 현재 프론트엔드(`App.tsx` 등) 내부에서 원본 문서를 띄워줄 때 `<iframe>` 형태로 해당 파일들을 불러와 하위 호환성(Backward-compatibility)을 유지하는 데 필수적인 역할을 합니다.
* **`src/`**: 리액트 앱의 핵심 소스코드가 모두 모여있는 폴더입니다.
  * **`components/`**: 재사용 가능한 하위 UI 컴포넌트 폴더입니다.
    * `MapComponent.tsx`: GeoJSON 데이터를 바탕으로 지도를 렌더링하고, 위치에 맞는 폴리곤이나 핀을 표출해 주는 지도 전용 컴포넌트입니다.
    * `StandardViewer.tsx`: 파싱된 결과물이나 특정 포맷의 데이터를 일관된 규격으로 화면에 그려주는 범용 뷰어 컴포넌트입니다.
  * `App.tsx`: 최상위 라우팅 및 뷰 전환(대시보드 화면 ↔ 인라인 편집 화면 등)을 관장하는 메인 컴포넌트입니다.
  * `DelegationManagementModal.tsx`: 사용자 권한 또는 작업 위임 관리를 위한 모달입니다.
  * `DictionaryModal.tsx`: 장비 사전, 공종 사전 등을 조회/수정할 때 띄우는 모달(팝업) 컴포넌트입니다.
  * `EditModeModal.tsx`: 특정 데이터의 상세 편집 모드로 진입하기 위한 모달입니다.
  * `EditTabConstructionInfo.tsx`: 인라인 편집 화면 내 "공사 정보(날씨, 누계 인원 등)"를 담당하는 탭 컴포넌트입니다.
  * `EditTabStatusTables.tsx`: 인라인 편집 화면 내 "장비 및 인원 현황표"를 담당하는 탭 컴포넌트입니다.
  * `EditTabWorkInput.tsx`: 인라인 편집 화면 내 "작업 내용 상세 입력"을 담당하는 탭 컴포넌트입니다.
  * `index.css`: 글로벌 스타일링 및 폰트, 색상 등 공통 CSS가 정의된 파일입니다.
  * `InlineEditView.tsx`: 일일작업보고 데이터를 표 형태로 보면서 직접 수정할 수 있는 핵심 에디터 화면 컴포넌트입니다.
  * `LocationDictionaryModal.tsx`: 위치 기준 사전 데이터를 조회/수정할 때 띄우는 전용 모달 컴포넌트입니다.
  * `main.tsx`: React 앱을 DOM에 렌더링하는 진입점 소스입니다.
  * `Phase3Dashboard.tsx`: 공구별 데이터 통계 및 시각화 요약 정보를 보여주는 메인 대시보드 화면 컴포넌트입니다.
* **`index.html`**: 리액트 앱이 브라우저에 가장 처음 로드될 때 렌더링되는 최상위 진입점(Entry Point) HTML 파일입니다.
* **`package-lock.json`**: `package.json`에 명시된 패키지들의 정확한 버전 트리를 고정(Lock)하여, 다른 개발 환경에서도 동일한 패키지 버전이 설치되도록 보장하는 파일입니다.
* **`package.json`**: 프로젝트에서 사용하는 NPM 패키지 목록과 구동 스크립트(`dev`, `build` 등)가 정의된 파일입니다.
* **`replace_layout.js`**: HWP 뷰어 등 레거시 화면의 DOM 레이아웃 구조를 동적으로 재배치하고 수정하기 위해 사용되는 헬퍼 스크립트입니다.
* **`replace_layout_scroll.js`**: 레거시 레이아웃 화면에서 스크롤 이벤트를 제어하거나 스크롤 영역을 보정하기 위한 스크립트입니다.
* **`replace_tooltip.js`**: 대시보드나 편집 화면에서 텍스트 오버플로우나 마우스 오버 시 커스텀 툴팁을 동적으로 생성하여 띄워주는 스크립트입니다.
* **`tsconfig.json` & `tsconfig.tsbuildinfo`**: TypeScript 컴파일러 설정 및 컴파일 속도 향상을 위한 빌드 캐시 정보 파일입니다.
* **`vite.config.ts`**: 빠르고 경량화된 프론트엔드 빌드 툴인 Vite의 서버 및 빌드 설정 파일입니다.

## 2. 시스템 구동 방법

### 2-1. Backend 구동
1. **Python 환경 세팅**: Python 3.10+ 환경을 준비합니다.
2. **의존성 설치**: 백엔드 폴더 내에서 터미널을 열고 아래 명령어를 실행합니다.
   ```bash
   pip install -r requirements_server.txt
   ```
3. **환경변수 세팅**: `.env` 파일에 타겟 DB(PostgreSQL) 접속 정보가 올바르게 기입되어 있는지 확인합니다.
4. **서버 실행**: `backend` 폴더 최상단의 배치 파일을 실행합니다.
   ```cmd
   .\run_server.bat
   ```
   *정상 실행 시 FastAPI가 8000번(또는 설정된 포트)으로 기동됩니다.*

### 2-2. Frontend 구동
1. **Node.js 세팅**: Node.js 18+ 버전을 준비합니다.
2. **의존성 설치**: 프론트엔드 폴더 내에서 터미널을 열고 아래 명령어를 실행합니다.
   ```bash
   npm install
   ```
3. **앱 실행**: 아래 명령어로 Vite 개발 서버를 구동합니다.
   ```bash
   npm run dev
   ```
4. **접속**: `http://172.16.40.94:5173/` (또는 로컬호스트 환경에 맞는 링크)로 접속하여 웹 UI가 정상적으로 노출되는지 확인합니다.
