## 📌 [사전 인지 사항] STA와 STA Range의 취급
현재 데이터 구조상 STA(단일 값)와 STA Range(구간 값)가 동시에 존재하는 경우는 없습니다.



## <📍CASE 1>: STA (or Range) 존재 O / Location 미존재 X
로직: 기존에 공유해 드렸던 '공구별 본선 road_id 리스트(way.json)'의 STA 범위를 기준으로 매핑하여 표출합니다. (Location 없이 STA 만 있을때 자동으로 본선 기준으로 표출할 road_id 리스트)

### [공구별 본선 road_id STA 범위]
#### 1공구: 
road_id 1 (0 ~ 2+669), 
road_id 3 (2+669 ~ 4+295),
road_id 4 (4+300 ~ 4+522), 
road_id 5 (4+517 ~ 5+783), 
road_id 7 (5+787 ~ 6+456)
road_id 10 (6+460 ~ 8+500)
#### 2공구: 
road_id 1 (6+500 ~ 12+524),
road_id 4 (12+520 ~ 16+900)

#### 3공구: 
road_id 1 (15+860 ~ 16+920),
road_id 4 (16+916 ~ 17+273)
road_id 2 (17+273 ~ 21+245)

#### 4공구: 
road_id 1 (21+250 ~ 25+500)

### 🚨 [CASE 1의 예외 상황 및 해결]

#### 에러 1. 매핑되는 road_id가 2개 이상 겹칠 때
해결: 중복 탐색 시 숫자가 더 낮은(작은) road_id를 우선하여 표출합니다.
(ex. STA.4+520 입력 시 1공구의 road_id 4, 5 범위에 모두 해당됨 -> 더 낮은 road_id 4에 표출)

#### 에러 2. 해당 공구의 범위를 벗어나는 경우 (타 공구 데이터 오기입 등)
해결: 해당 공구 way.json에서 탐색이 안 되면, 타 공구의 way.json 데이터를 스캔하여 맞는 범위의 공구에 표출합니다.
(ex. 4공구 데이터인데 STA.21+000 입력됨 -> 4공구 범위(21+250~) 이탈 -> 전체 스캔 후 3공구 데이터로 매핑)

## <📍CASE 2>: STA (or Range) 존재 O / Location 존재 O
로직: Location Dictionary 테이블을 우선 조회하여 기준2 (road_id)를 찾은 뒤, 해당 road_id 노선 위에서 입력된 STA 위치(또는 구간)를 표출합니다.

| proj_cd   | name | detail_name | direction | sta_start | sta_end   | standard2 |
| --------- | ---- | ----------- | --------- | --------- | --------- | --------- |
| section_2 | R-A  | -           | -         | 0+000.752 | 0+735.366 | 12        |

[처리 예시]
2공구 
Location: R-A / - / - /
Station: STA.0+100 ~ STA.0+750

딕셔너리 조회 결과: Depth1: R-A의 standard2 (road_id)가 12임을 확인.
결과: road_id가 12인 노선 위에 STA.0+100 ~ 0+750 구간 표출.

## <📍CASE 3>: STA 미존재 X / Location 존재 O
로직: STA 값이 없으므로, Location Dictionary 상의 STA 시작점과 종료점의 '중간값(Midpoint)'을 계산하여 단일 포인트로 표출합니다.

[처리 예시]
2공구 
Location: R-A / - / - / 
Station: 없음(NULL)

딕셔너리 조회 결과: STA 시작: 0+000.752, STA 종료: 0+735.366

결과: 0.752와 735.366의 중간값인 368.059 지점에 표출.
